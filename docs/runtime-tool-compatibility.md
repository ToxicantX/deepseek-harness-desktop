# Runtime 工具兼容

桌面壳通过启动预加载钩子适配运行时模块，不写入 DSH 核心文件。当前适配依据为本机 DSH 0.1.3-alpha.1；模块特征不匹配时保留原实现并输出警告。

## PowerShell

自动发现候选可执行文件时，使用隐藏窗口、无配置文件的 `exit 0` 探测其启动能力，单个候选最多等待 3 秒。跳过启动失败的 WindowsApps 别名，继续使用 DSH 原有候选顺序，包括系统 Windows PowerShell。显式配置的 `pwshPath` 保持原语义，不偷偷换成其他程序。

执行前检查工作目录；如 `E:AIproject` 这样的盘符相对路径会提示使用绝对路径，目录缺失或不可访问会单独报错。不会猜测丢失的目录分隔符，不重试用户命令。

无需下载工具或修改系统 PATH。探测发生在执行器解析程序路径时，不是每条命令都启动探测。更新壳并重新启动后生效；已运行的 DSH 不受源码编辑影响。

## 代码解析错误

附件的两段失败代码在相同的 Node 类型擦除入口均可复现：第一段普通单引号字符串包含实际换行；第二段存在 `"new_string:"async ...` 这样的错误字段引号。不是缺少 async 支持，也不是缺少工具。

壳侧在共享 TypeScript SDK 指引中补充字符串转义、短调用和 Windows 绝对路径要求，并在执行器创建 worker 之前的解析失败中追加具体操作提示。普通语法失败不重试、不执行工具；“工具尚未执行”只描述本次解析失败的调用，不覆盖历史调用。仅下述严格限定的 PowerShell `String.raw` 形态会进行一次等价文本转换和重新解析。

针对 PowerShell 常见的反引号换行写法，增加一个严格限定的解析前修复：仅当首次 TypeScript 解析失败、表达式以换行后的 `String.raw\`` 开始、结束反引号独立成行并紧跟 `.trim()`、正文包含反引号且没有 `${...}` 模板插值时，壳将正文编码为等价普通字符串并重新解析一次。命令文本中的 PowerShell 反引号、百分号、美元变量及换行保持原值，工具仍只执行一次。

不符合上述形态的模板继续走原失败路径，避免改变 JavaScript 插值语义。共享提示优先建议把复杂 PowerShell 写成字符串数组后 `.join("\\n")`；限定修复用于吸收模型仍生成 `String.raw` 多行命令的情况。例如附件中的 curl `TOTAL=%{time_total}\`n` 片段会命中该修复。

## 压缩会话日志

现有 `read` 工具仅对 `.jsonl.zstd` 后缀增加解压读取，不新增独立工具，因此使用该工具模块的主代理和子代理共享此能力。仍通过原有路径解析、普通文件检查及 `ctx.fs.readBytes` 读取，不通过 Node 文件 API 绕过文件服务。

压缩输入上限 16 MiB，解压总量上限 64 MiB，超限报错，不返回假完整结果。逐个处理拼接的 Zstandard 帧，避免 Node 单次解压只读取第一帧；随后复用原工具的行号、offset、limit、行长与输出字节限制。支持读取取消检查；单帧解压期间取消将在该帧结束后生效。每次分页仍需重新解压整个限额内文件，不承诺大日志高性能。

其他二进制格式保持原行为。工具描述提示解压范围与限额，不安装额外可执行程序。压缩日志读取可能包含会话正文，调用方应只请求任务需要的内容。

## 超量读取、编辑冲突与子代理调用

正整数 `read.limit` 超出当前部署上限时，按该上限返回一页，不提高原有资源限额；例如上限 2000 时请求 5000 返回至多 2000 行。负数、零、小数及其他无效值仍报错。工具参数说明明确这一行为；续读应使用最后实际返回行号加一，而非请求的 limit，结合 totalLines 判断是否读完。执行与结果渲染共用参数解析，避免读取成功后渲染再次因超量报错。

共享 TypeScript SDK 指引补充以下规则，属于减少模型误用，不保证消除所有错误：

- 外层 run_code 与内层子工具分别满足各自 schema 的必填参数，包括 description。
- 编辑前读取当前内容，old_string 应包含唯一上下文，不包含界面行号；匹配多处时扩大上下文，匹配不到时重新读取。同一文件串行编辑，保留精确匹配保护，不自动开启 replace_all。
- 仅使用当前工具结果确认的代理 ID，不从工具名称或其他会话推测父代理 ID；目标不可用时停止重复发送，正常返回任务结果。壳不伪造代理、不替换收件人。
- 长文件写入与验证命令分开提交；EOF 错误先检查截断及括号、引号闭合。String.raw 仍受反引号与插值语法影响，不能通过空字符串 replaceAll 补救源码。

截图和附件中的错误未包含壳版本及适配日志，因此仅凭错误文本不能确认上一轮兼容是否已在报错机器加载。新版仍需重新构建/部署后验证，已有错误历史不会被移除。

## Grep 正则与超时

现有 `grep` 增加可选 `literal` 参数。默认仍使用 ripgrep 正则；搜索 PHP 命名空间、方法调用或其他包含反斜杠、括号、方括号的源码原文时，使用 `literal: true`，命令会加入 `--fixed-strings`。多个精确关键词分别调用 grep，避免把源码转义、正则转义和 TypeScript/JSON 转义混在同一个长表达式中。

非法正则仍会阻止搜索，并在错误中明确提示 `literal: true`、分别搜索多个字面量及缩小 `path`/`include`。不把错误表达式自动转换后执行，避免错误转义被解释成另一个合法但含义不同的查询。

默认搜索预算由 30 秒提高到 60 秒；显式配置仍优先。主、子代理提示要求先限定目录和文件 glob，再重试宽泛或超时搜索。调用方主动取消仍立即结束，不以自动重试覆盖取消结果。工具继续使用 Runtime 自带的 `@vscode/ripgrep`，无需安装系统 rg。

## 重复文本的精确编辑

现有 `edit` 增加可选 `occurrence` 参数，用于 `old_string` 确实重复、但只应修改其中一处的情况。该值从 1 开始计数；例如读取文件确认目标是第二处后，传入 `occurrence: 2`。文件系统后端仍在原有目标锁、已读版本检查和原子写入流程内选择该匹配，不会先在壳外读取再覆盖整份文件。

`occurrence` 与 `replace_all` 互斥，零、负数、小数、超出实际匹配数量都会报错。未提供 occurrence 时保留原行为：唯一匹配正常编辑，多处匹配返回错误；错误信息会给出可用的 `1..N` 范围。这样不会在目标位置不明确时默认修改第一处，也不会把局部修改扩大为全量替换。

主、子代理提示同步要求：先读取当前文件；优先扩大 `old_string` 上下文，若上下文过长则使用已核对的 occurrence；同一区域每次编辑后重新读取。示例：

```typescript
await tools.edit({
  file_path: "application/common/service/ExcelImportService.php",
  old_string: "目标重复片段",
  new_string: "替换内容",
  occurrence: 2,
})
```

## 验证与回滚

使用 Node 24 执行 `node_modules/vitest/vitest.mjs run tests/runtime-tool-compatibility.spec.ts` 和 `node_modules/typescript/bin/tsc --noEmit`。

已安装 Runtime 模块的隔离冒烟入口：

```powershell
node scripts/smoke-runtime-tool-compatibility.mjs "C:\path\to\runtime"
```

此脚本检查五个实际模块的特征匹配、适配后语法与加载，实际启动 PowerShell 输出固定标记，验证损坏目录及解析失败分支，并调用实际注册的 read 工具验证合成拼接帧、分页及文件服务拒绝路径；同时验证 grep 的字面量 argv、60 秒默认值、工具 schema/提示，并使用 Runtime 自带 ripgrep 完成真实字面量搜索，最后核对核心文件哈希未变。不会启动 DSH 服务，也不代表真实主/子代理或打包应用验收。

冒烟还使用部署上限 20、请求 5000 的 45 行合成日志验证返回 20 行、续页从第 21 行开始、输出渲染正常及负数仍被拒绝。

运行时验收仍需在报错机器验证主代理及子代理的 PowerShell 调用。停用适配可删除 `src/shutdown-hook.ts` 中 `installRuntimeToolCompatibility` 的导入和调用，然后重新构建壳；不涉及用户会话或设置。
